## 协作规则

1. 不直接修改 `main` 分支。
2. 每个功能使用 `feature/<成员>-<功能>` 分支。
3. 一个 Pull Request 只解决一个功能。
4. 合并前至少由一名队友试玩或检查代码。
5. 每周结束创建一个可运行版本标签。
6. 共享状态由成员1维护接口，其他成员不得自行改变数据结构。
7. 每个成员必须能在自己的电脑上启动项目并完成一次本地测试。
8. GPT 生成的代码必须由负责人运行、理解并修改，不能直接把无法解释的代码合并进主分支。

## 会议节奏

- 每周一次 30 分钟计划会：确定本周交付物。
- 每周一次 30 分钟试玩会：四个人一起玩当前版本。
- 每天用 GitHub Issue 或群消息记录阻塞问题。
- 周末只讨论“已完成、未完成、阻塞原因、下周目标”四项。
