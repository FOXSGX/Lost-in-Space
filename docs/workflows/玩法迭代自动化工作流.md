# 《迷失太空》玩法迭代自动化工作流

状态：工作流已接入并通过自检；尚未把任何新建议写入星球设计或代码。

## 目的

把已有星球的玩法、关卡、剧情、故事、交互、机制、地图和自由探索问题，转换成可验证的设计假设，再用 Godot 的自动测试、真实联机冒烟测试和截图记录反馈，决定下一轮最小改动。

## 固定闭环

```text
读取项目真源
  → 设计 Skill 生成候选方案
  → Reality Check 识别最弱假设
  → 写 Godot 测试计划
  → 运行自动测试/联机测试/截图捕获
  → 归档观察事实和用户试玩反馈
  → 选择下一轮最小验证
  → 用户批准后才修改代码或正式设计文档
```

## 目录约定

每一轮写入 `work/gameplay-iterations/<iteration-id>/`：

| 文件 | 内容 |
| --- | --- |
| `00-context.md` | 目标、范围、读取文档、状态标记和文件哈希 |
| `02-design-options.md` | 至少两个结构不同的玩法/关卡/剧情方案 |
| `03-reality-check.md` | 事实、推导、假设、未知和最弱因果链 |
| `04-test-plan.md` | Godot 测试入口、步骤、观察信号和通过条件 |
| `05-test-report.md` | 自动测试、联机测试和截图捕获结果 |
| `06-feedback.md` | 玩家原话、观察、影响和下一轮问题 |
| `iteration.json` | 机器可读的套件、状态、退出码和文件哈希 |
| `logs/` | 每个 Godot 测试的 stdout/stderr |

## 测试分层

### 规则和状态层

用于确认机制、检查点、故事标记、长期探索状态和失败恢复没有违反设计规则：

- 共振星：`resonance_stage.gd`、`resonance_runtime.gd`
- 共振星运行时定位：`resonance_runtime_probe.gd`
- 共振星资源诊断：`resonance_scene_diagnostic.gd`、`resonance_spawn_isolation.gd`
- 两星球 UI/目标截图：`iteration_planet_capture.gd`
- 真实两星球联机握手：`iteration_network_smoke.gd`
- 主舱存档诊断：`ship_hub_persistence_diagnostic.gd`
- 故事：`story_arc.gd`
- 探索与支线：`campaign_systems.gd`、`exploration_features.gd`

### 流程和联机层

用于确认船舱、返航、多人同步、掉线回库和真实 RPC 流程：

- `ship_hub_integration.gd`
- `ship_hub_network.gd`

### 空间和交互层

用于确认地图可达性、交互点、输入反馈和场景截图：

- `reachability.gd`
- `field_interactions.gd`
- `capture_view.gd`

自动测试通过只说明规则或流程满足脚本断言，不能单独证明玩家理解、紧张感、故事记忆点或自由探索价值。

## 用户反馈处理规则

用户反馈先进入迭代目录，分为：

- `观察事实`：玩家实际卡住、误解、重复尝试或放弃的行为；
- `问题解释`：对原因的推断；
- `待讨论方案`：可能的改法；
- `验收问题`：下一轮要回答的最小问题。

反馈中的 P0/P1/P2 只是优先级建议，仍需经过设计 Skill 和 Godot 测试验证后再决定是否修改。

在项目根目录运行：

```powershell

.\tools\gameplay-iteration.ps1 -Suite resonance-spawn-isolation
.\tools\gameplay-iteration.ps1 -Suite resonance-core-release
.\tools\gameplay-iteration.ps1 -Suite resonance-extraction
.\tools\gameplay-iteration.ps1 -Suite resonance-single
.\tools\gameplay-iteration.ps1 -Suite functional-extra
.\tools\gameplay-iteration.ps1 -Suite visual
.\tools\gameplay-iteration.ps1 -Suite planet-visual
.\tools\gameplay-iteration.ps1 -Suite full
.\tools\gameplay-iteration.ps1 -Suite hub
.\tools\gameplay-iteration.ps1 -Suite network
.\tools\gameplay-iteration.ps1 -Suite planet-network
.\tools\gameplay-iteration.ps1 -Suite all
.\tools\new-gameplay-iteration.ps1 -Scope "共振星核心搬运" -Objective "验证倒地后核心是否能重新接入"
.\tools\validate-gameplay-workflow.ps1 -IterationId 20261014-170000-spawn-constants-fixed
```

脚本只读取项目和运行测试，默认不修改 `game/`、`docs/design/` 或 `art-source/`。

编排器不会把 Godot 进程的 0 退出码直接当作通过：脚本解析失败、脚本加载失败、空场景实例化失败和测试输出中的显式失败标记都会使该套件失败。这是为了防止 Godot 在脚本加载异常时产生假绿。

`validate-gameplay-workflow.ps1` 会检查项目 Skill 的 frontmatter、编排器入口、诊断测试、迭代产物和 `iteration.json` 中记录的源文件 SHA-256；哈希变化只说明需要重新归档或复测，不会自动回写任何正式设计或游戏代码。

`new-gameplay-iteration.ps1` 只创建标准迭代材料和日志目录。它不会修改 `game/`、`docs/design/` 或 `art-source/`，也不会把反馈中的方案自动写成设计决定。
