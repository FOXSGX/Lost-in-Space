# 共振星（Resonance / `electromagnetic`）上线前全流程技术审计

- 审计时间：2026-11-23
- 引擎：Godot 4.7.2.stable（`GL Compatibility`，`occlusion_culling=true`）
- 物理：Jolt Physics，60 Hz，5 层：`1 world / 2 player / 3 interactable / 4 machine / 5 trigger`
- 审计方式：**逐文件阅读 + Godot CLI 实测探针**，两类结论严格分栏
- 结论标记：**未标注者默认是`【实锤】`**（已在源码中逐行核对过该行/该函数）；标`【待复现】`的是静态推断，需实机或补充探针确认（如 R-25、R-28、R-32 的部分后果）。

## 0. 结论摘要（先看这里）

1. **本次未发现“必现 P0”**：8 个实测探针里没有任何一项在默认流程上必然卡死或必然穿模。但有 **4 条 P1 的后果是“流程中断、只能靠重置或反复重试”**，属于上线前必须处理：
   - `R-01`（出口门状态折叠 → 出口永久不可达，必须整关重置并丢记忆进度）
   - `R-02`（货舱夹具释放不复位 → 第二次装载必失败）
   - `R-03`（晶体被误登记为货舱货 → 夹具永不闭合、开动即掉落）
   - `R-35`（Act1 锁爪堵转把马达冲量清零，判据窗口仅 ±0.10 rad ≈ 6 cm → 反复按 E 夹不上）
2. **两条检查清单假设被实测推翻**，不要再按“缺陷”去改：
   - `AnimatableBody3D.sync_to_physics = false` **不影响载人**。自建探针：载人漂移 ≈ 1e-7 m，`platform_velocity` 正确读数 1.45 m/s；反而 `true` 时载人下陷 0.41 m。**现行写法是对的，不要改成 true。**
   - 矿车**不会**因速度隧穿：1.55 m/s = 25.8 mm/tick，甲板碰撞体 180 mm，且有牵引力上限（1200 N）与调节器（2500 N）双重限速，代码里不存在超过 `CRUISE` 的路径。
3. **清单里的一批地点在现行版本中不存在**（5.4 m 观景桥、11.5 m 高位竖井台、3 条登高坡道、反应堆塔、熔岩判定）。第 2 节给出“清单地点 → 现行实现”的映射，避免继续按旧稿找 bug。
4. **工具链是最大的“虚假安全感”，而且是双重的**（`R-12`）：
   - `tools/gameplay-iteration.ps1` 引用的 **9 个共振星测试脚本在仓库里不存在**；
   - 更要紧的是，Act1 / Act2-3 / Act4 的三个端到端驱动（`act1_autotest`、`a23_flow`、`a4_flow`）分别是 `Node` / `RefCounted`，**根本不是 `--script` 能跑的入口**；我实测 `--script act1_autotest.gd` 空转 45 分钟、CPU 0.55 s、零输出。也就是说：**目前没有任何一条能在 CI 里独立跑的“共振星全流程回归”**，`smoke/resonance/full` 三个套件不可能证明上线安全。
5. 性能：Act5 大厅 1280×720 无 vsync 实测 **p50 15.9 ms / p95 20.6 ms / max 38.4 ms**，**4378 draw call / 36 盏灯 / 376k 三角**。均值达标，但 38 ms 尖峰与 4378 draw call 在 GL Compatibility 下偏低端机器有风险（`R-33`）。
6. **联机是第二个“看起来能用、实测会翻车”的区域**（`R-46 ~ R-53`）。实测节流参数：快照 **15 Hz**、位姿 **20 Hz**，但**没有去重、没有差分、没有阈值**，机械位姿也**没有 dirty check**；并且 Act4 的快照走裸 `rpc()`，**绕过了 Act5 已有的 `CoopSnapshotWire`（Zstd + 768 B 分片 + 校验）**。最硬的三个是：客户端与主机**双重模拟**同一颗 16 kg 晶体（`R-46`）、远端玩家位姿**硬赋值**导致丢包穿墙（`R-47`）、以及 `highest_completed_seq` 不复位导致**重连后客户端约 5 分钟收不到任何快照**（`R-48`）。

## 4. 问题明细

> 编号规则：`R-xx` 为全局序号；等级 `P0 阻断通关/必现穿模卡死`、`P1 严重物理异常/频繁卡顿`、`P2 轻微隐患/边界瑕疵`。
> 每条包含：定位 / 触发机理与根因 / 复现步骤 / 最小修改方案 / 验证方式。

### P1（上线前必须处理）

#### R-01 出口升降门被“折叠成 open”，门卡在半高且 `open()` 永久拒绝 → 只能整关重置
- **定位**：`game/scripts/act4/exit_gate.gd : close_gate()`（537–544）、`open()`（516–522）、`_update_travel_state()`（741–800）；调用方 `game/scripts/act4/memory_director.gd:585`（**每段记忆结束都会调 `close_gate()`**）
- **触发机理与根因**：`close_gate()` 在门口有人时执行 `_state = "open" if height > 0.05 else "closed"`（540）。若此刻门还在上升途中（`height` 介于 0.05 与 `REQUIRED_CLEARANCE=4.20` 之间），状态被硬改成 `"open"`；而 `open()` 第 521 行 `if _state == "opening" or _state == "open" or is_open: return` 直接返回，于是：门既不再上升，也不允许重新下令；`hold_mode` 只有在 `height > 4.15` 时才为 `"motor"`（770），因此 `hold_mode="none"`、`stable=false`（776–777）、`exit_allowed` 恒 `false`。**玩家唯一出路是按 R 整关重置，而 `reset_level()` 会清空 `seen_memories`/`stage`（`game.gd:871-874`），等于丢掉全部记忆进度。**
- **复现步骤**：①推进到记忆 3（`game.gd:536-538` 执行 `gate.unlock("memory_3")` + `gate.open()`）；②在门上升的约 2.9 s 内（`V_OPEN=1.6`，`H_OPEN=4.60`）站进门洞体积；③保持站立直到该段记忆结束触发 `close_gate()`；④门停在 2–4 m，此后反复交互/等待都无效。
- **最小修改方案**：状态必须由**真实高度**决定，不允许把运动态折叠成静止态：
```gdscript
# exit_gate.gd close_gate()
if _doorway_occupied():
    _state = "opening" if height < REQUIRED_CLEARANCE else "open"
    _retract_catch()
    gate_notice.emit("门口有人，升降门保持开启")
    return
```
```gdscript
# exit_gate.gd open()
if is_open:
    return
if _state == "opening":
    return
if _state == "open" and height < REQUIRED_CLEARANCE:
    _state = "opening"          # 半开门必须能被重新驱动
    drive_enabled = true
    powered = true
    return
```
- **验证方式**：新增断言到 `game/tests/test_flow.gd`（或独立探针）：先 `gate.unlock("t")`、`gate.open()`，等 `height` 到 2.5 时把玩家 `teleport` 到门口体积内，调 `close_gate()`，随后断言 `gate._state == "opening"` 且 400 帧内 `exit_allowed == true`。

#### R-02 货舱夹具释放路径不复位 → 第二次装载的晶体必被弹出/无法固定
- **定位**：`game/scripts/act4/freight_platform.gd : _tick_cargo()`（974–1000）、`_drop_cargo_overboard()`（1057–1075）、`release_cargo()`（1602–1620）、`release_cargo_silent()`（1643–1657）、`_tick_clamp()`（1005–1055）
- **触发机理与根因**：压板与四个侧挡的位移只在 `_tick_clamp()` 里推进，而 `_tick_clamp()` **只在 `cargo` 已注册时被调用**（975–976 提前 `return`）。释放/掉落路径只写了 `clamp_closed = false`，**没有把 `_press_y` 复位到 `PRESS_OPEN_Y=1.80`、也没有把 `_chock_pos` 复位到 `CHOCK_OPEN=1.20`**，于是四个侧挡碰撞体永久停在 `CHOCK_INNER=0.388`、压板永久停在 ~1.14 m。下一次把晶体放上甲板时：侧挡内表面（0.388 − 0.05 = 0.338）小于晶体半径 0.34，**静态重叠 2 mm**；压板已在顶部高度，`jaw_pressing/jaw_locked` 会立即为真但物理上压不到晶体。Jolt 用穿透修正把 16 kg 晶体弹开，`is_cargo_fixed()` 与真实接触脱钩。

```gdscript
    ...
    _prev_deck_xform = deck.global_transform
```
```gdscript

var target_tilt: float = clampf(tilt + impulse, -_max_tilt(), _max_tilt())
tilt = move_toward(tilt, target_tilt, delta * 1.2)
```

- **定位**：`game/scripts/act4/freight_platform.gd:668-673`（`_physics_process` 非权威分支 `return`）、`:1789-1790`（`if cargo_attached and cargo == null: pass`）、`:1005-1050`（`_tick_cargo` 只在权威分支被调用）；关联 `game/scripts/act4/game.gd:1262`（`crystal.global_position = pos`，15 Hz 直写活刚体）

#### R-47（P1，审计方判 P0，本条下调）远端玩家硬赋 `global_position` → 丢包即穿墙/瞬移
- **定位**：`game/scripts/act4/player_controller.gd:926-934`（`update_remote_state` → `global_position = world_position`、`velocity = remote_velocity`），调用方 `game/scripts/act4/game.gd:1477`、`:1398`

```gdscript

    var error: float = global_position.distance_to(world_position)

```
- **验证方式**：双进程用例：人为丢弃 5 个连续快照后，断言远端体单帧位移 < 0.35 m 且未进入墙体（用 `test_move` 或 `intersect_shape` 断言）。

#### R-48（P1）`highest_completed_seq` 从不复位 → 重连后客户端 5 分钟收不到任何快照
- **定位**：`game/scripts/coop/snapshot_assembler.gd:21`（成员）、`:36-44`（`reset()` 只清 `_parts` 等）、`:58-59`（`if seq <= highest_completed_seq: return "stale"`）、`:124`（唯一写入点）；调用方 `game/scripts/coop/coop_net.gd:185-192`（`_reset_snapshot_wire_state`，在每次 Act 重绑 `:779` 与每次重连 `:2432` 调用）
- **触发机理与根因**：`reset()` 清空分包缓冲却**不清 `highest_completed_seq`**，而它按会话生命周期单调递增。主机重启/断线重连后主机的 `_seq` 从 0 重新计数，客户端会把每一个包判为 `stale` 全部丢弃，直到主机计数追上旧值（15 Hz 下约 4700 个包 ≈ **5 分钟**）。这段时间客户端画面完全冻结在旧状态。
- **复现步骤**：双端联机进入 Act5 → 关闭主机进程再重开（客户端不断开）→ 客户端不再更新，直到数分钟后突然跳变。
- **最小修改方案**：
```gdscript
func reset() -> void:
    active_seq = -1
    ...
    _parts.clear()
    highest_completed_seq = -1        # ← 关键：会话级序号必须随会话重置
```
（若希望跨会话保留用于重放保护，则改为 `reset_session()` 并在 `_reset_snapshot_wire_state()` 里显式调用。）
- **验证方式**：`net_snapshot_audit.gd` / `test_snapshot_wire.gd`：构造 seq 1000 完成后调用 `reset()`，再喂 seq 0..5，断言状态为 `partial/complete` 而非 `stale`。

#### R-49（P1）Act4 快照 15 Hz 全量重发、无去重，且绕过了 `CoopSnapshotWire` 的 MTU/压缩保护
- **定位**：`game/scripts/coop/coop_net.gd:1815-1821`（`_act4_snap_clock` 计满即 `act4_sync.rpc(act4_game.build_act4_snapshot())`）、`game/scripts/act4/game.gd:1408-1444`（`build_act4_snapshot()`，含 `"ledger": {}`）
- **触发机理与根因**：①即使平台停靠、无人移动，也每 1/15 s 重建并广播整包（15 个顶层键 + 22 个平台键 + 每人 5 键；2 人约 47 字段）；②`"ledger": {}` 空字典也照发；③走的是裸 `rpc()` 的 Variant 序列化，**没有** `CoopSnapshotWire` 的 Zstd 压缩、768 字节分片、FNV-1a 校验与 1200 字节预算 —— 4 人时体积逼近 ENet 1392 字节 MTU，一旦超限就是静默分片/丢弃。Act5 用的是 `CoopSnapshotWire`，Act4 没有。
- **最小修改方案**：三段式——去重、瘦身、走线：
```gdscript
var _last_act4_snap: Dictionary = {}

func _act4_host_process(delta: float) -> void:
    _act4_snap_clock -= delta
    if _act4_snap_clock > 0.0:
        return
    _act4_snap_clock = 1.0 / SNAPSHOT_HZ
    var snap: Dictionary = act4_game.build_act4_snapshot()
    snap.erase("ledger")                      # 空账本不随包发
    if snap == _last_act4_snap:
        return                                # 静止时不发
    _last_act4_snap = snap.duplicate(true)
    for packet: PackedByteArray in CoopSnapshotWire.encode_packets(snap, _next_seq()):
        act4_sync_packet.rpc(packet)
```
- **验证方式**：`net_snapshot_audit.gd`：静止 10 s 断言发送包数 < 5；4 人快照断言每包 ≤ 1200 字节且校验通过。

#### R-50（P1）`apply_net_state` 对每个字段零校验 → 版本偏移或坏包可把甲板写成 NaN/越界
- **定位**：`game/scripts/act4/freight_platform.gd:1763-1768`（`_net_x = float(state.get("x", _net_x))` 等）、`:1799-1808`（`lerpf` 直接写入 `global_position`）；同类 `game/scripts/act4/game.gd:1475`（`float(state.get("yaw", 0.0))`）、`:1479-1482`（`snap.get("crystal_a_pos", Vector3.ZERO)`）
- **触发机理与根因**：没有任何类型/范围/有限性校验。坏包或版本偏移时：`float("abc")` 抛错、`float(NAN)` 直接污染 `_net_x`，随后 `lerpf` 把它写进 `global_position` → 物理状态非法（控制台刷 `physics state is invalid`）；即使是“合法但过期”的值，也能把甲板写到 `[far_park_x, near_park_x]` 之外。`crystal_a_pos` 字段名一旦改名，`Vector3.ZERO` 默认值会把两颗晶体**瞬移到世界原点**（穿过岩体）。Act5 有 `_snapshot_shape_ok()`，Act4 什么都没有。
- **最小修改方案**：一次性整体校验，坏包整包丢弃：
```gdscript
func _snapshot_ok(state: Dictionary) -> bool:
    for key: String in ["x", "y", "speed", "roll", "pitch"]:
        var value: Variant = state.get(key, null)
        if value == null or not (value is float) or not is_finite(float(value)):
            return false
    var x: float = float(state.get("x", travel_x))
    return x >= far_park_x - 0.5 and x <= near_park_x + 0.5

func apply_net_state(state: Dictionary) -> void:
    if not _snapshot_ok(state):
        push_warning("ACT4 platform snapshot rejected")
        return
    ...
```
并把 `crystal_a_pos` 缺失语义改为“保持当前”，而不是 `Vector3.ZERO`。
- **验证方式**：`net_snapshot_audit.gd`：投喂 `{"x": NAN}`、`{"x": "abc"}`、缺字段包，断言甲板位姿不变且无 `SCRIPT ERROR`。

#### R-51（P2）`remove_player` 不清 `grab_states`/`player_states`，且发出了错误的状态
- **定位**：`game/scripts/coop/coop_session.gd:106-115`（`remove_player`），`:44-45`（两个字典）、`:64/:246`（`grab_states` 写入）、`:260`（`player_states` 写入）、`:251-256`（`current_grab_pids()`）
- **触发机理与根因**：离场只清了 claim 与 ledger，两个状态字典**永久保留**该 pid：①跨加入次数无界增长；②`current_grab_pids()` 仍把已断开的 pid 报成“正在抓握”，而 `surge_director.gd:141/:191` 正是读它；③`coop_net.gd:2073-2080` 会把每个离场 pid 的冻结状态**永久塞进每一个 Act5 快照**。另外 `:114` 刚存了 `STATUS_DISCONNECTED`，紧接着却 `emit(pid, STATUS_SPECTATOR)`，监听者拿到的是错的状态。
- **最小修改方案**：
```gdscript
func remove_player(pid: int, reason: String = "disconnect") -> void:
    ...
    release_all_for(pid, reason)
    grab_states.erase(pid)
    player_states.erase(pid)
    ledger.set_status(pid, ParticipationLedger.STATUS_DISCONNECTED)
    status_changed.emit(pid, ParticipationLedger.STATUS_DISCONNECTED)   # 与存储一致
```
- **验证方式**：`test_participation.gd`：2 人加入 → 1 人断开 → 断言 `grab_states.size()==1`、`current_grab_pids()` 不含该 pid、`status_changed` 收到的是 `DISCONNECTED`。

#### R-52（P2）`_act4_ready04_seen` 只增不清，且会掩盖重连后的验收日志
- **定位**：`game/scripts/act4/game.gd:60`（声明）、`:1519-1521`（`_act4_ready04_seen[pid] = true` 后据此去重打印）、`on_act4_peer_disconnected`（`:1757-1779`，未清理）、`_teardown_coop`（`:1792-1806`，未清理）
- **触发机理与根因**：每有一个曾连过的 pid 就多一条，生命周期等同 CoopNet 节点；若 pid 被复用，`AUTHORITY_SYNC` 那行验收日志会被抑制 —— 恰好把这条日志存在的意义抹掉。
- **最小修改方案**：`on_act4_peer_disconnected` 里 `_act4_ready04_seen.erase(pid)`；`_teardown_coop` 里与 `coop_players.clear()` 一起 `_act4_ready04_seen.clear()`。
- **验证方式**：`r8c04_transition_probe.gd` 类用例：连→断→同 pid 重连，断言 `AUTHORITY_SYNC` 再次打印。

#### R-53（P2）`carry_changed.connect` 缺 `is_connected` 守卫；`_signals_wired` 单向锁存
- **定位**：`game/scripts/act4/game.gd:1021-1023`（`player.carry_changed.connect(_on_coop_carry_changed)`，下一行 `pickup_requested` 却有 `is_connected` 守卫）、`game/scripts/coop/coop_net.gd:297-299`（`if _signals_wired: return` / `_signals_wired = true`）
- **触发机理与根因**：①`carry_changed` 是绑定路径里唯一没守卫的 connect，任何不经 `_teardown_coop()` 的重绑都会**双连**，于是每次拾取/放下被转发两次 → **一颗晶体拿两份参与度**；②`_signals_wired` 只置位从不清零，进程内“重新主持 / 主机↔客户端切角色”时复用同一 CoopNet 节点会提前返回，新角色的 `connected_to_server`/`peer_connected` 从未连上，会话表现为单向。
- **最小修改方案**：
```gdscript
if not player.carry_changed.is_connected(_on_coop_carry_changed):
    player.carry_changed.connect(_on_coop_carry_changed)
```
```gdscript
func _rewire_signals() -> void:
    for sig: String in ["connected_to_server", "connection_failed", "server_disconnected",
                        "peer_connected", "peer_disconnected"]:
        var callable: Callable = Callable(self, "_on_" + sig)
        if multiplayer.multiplayer_peer != null and multiplayer.is_connected(sig, callable):
            multiplayer.disconnect(sig, callable)
    _signals_wired = false
    _ensure_signal_wiring()
```
- **验证方式**：`test_act4_participation.gd`：连续两次 `_setup_coop()`，断言 `carry_changed` 的 `get_connections()` 数为 1，且一次拾取只产生 1 点参与度。

## 6. 需人工进游戏重点手测的力学手感 / 联机边界项

> 这些项**静态审计无法定论**，必须在真机（含低端显卡）上手测，建议按顺序一次性过完并录屏。

1. **载具带人（Act2-3 矿车 / Act4 悬吊平台 / Act5 步桥）**
   - 站车顶 → 起步 / 刹车 / 过弯 → 下车瞬间速度是否叠加飞出；站在边缘时是否被“甲板抽走”。
   - 实测已证明 `sync_to_physics=false` 能正确带人；重点转为**下车瞬间的动量**与**倾斜时**的表现。
2. **刹车与惯性**：满速急刹（notch 2）→ 停距是否符合直觉（矿车 ≈0.97 m / 平台 ≈2.16 m）；斜坡静止是否蠕动；刹停后是否抖动。
3. **货箱/晶体质量比**：晶体 16 kg vs 平台 150 kg / 矿车 1650 kg。要求手测“人踩上去车被弹飞”“小晶体把吊篮压翻”是否出现（按数值不应出现，但要验证释放瞬间的弹出）。`【R-02/R-20】`
4. **夹具和叉口**：偏心 0.15/0.25/0.30 m 三种放法各合爪 5 次，记录是否弹出。`【R-05】`
5. **出口门**：门上升途中站进门洞、门下降途中走进门洞、晶体留在门口，三种情况各试一次。`【R-01/R-19】`
6. **锤击手感**：满力/半力各打 5 次，确认撞击帧视觉贴合（`【R-15】`，几何已由 `tests/act4_hammer_impact.gd` 实测为重叠 0.133 m，**只需看锤头是否穿过摆弧里的玩家**），并在 30/60 fps 下比较强度是否一致（`【R-16】`）。
7. **第三人称相机**（Act2-3 洞内 15 m 远景 + Act4 洞窟）：贴墙、上坡、站在 8 m 轨道下方、进入隧道口、切第一人称操作机台，各看一次是否穿壁/闪现。`【R-13/R-14】`
8. **单人 Z 无人机与多人互斥**：单人下 12 s 持续 / 8 s 冷却的边界（过期瞬间、角色切换、单人转多人）是否把机关留在半锁状态。**注意：`resonance_drone` 动作在共振星代码里没有任何处理**（仅 `space_player_3d.gd:448` 与截图脚本引用），若该功能被承诺给玩家，这是一个**功能缺失**而不是边界 bug。
9. **联机往返（必须双进程真机，不能只看单机）**
   - **重连**：进 Act5 → 关闭主机进程重开（客户端保持）→ 客户端是否约 5 分钟不更新（`【R-48】`）。
   - **掉包/卡顿**：主机侧制造 300 ms 卡顿或丢 5 个快照 → 远端玩家是否穿墙、晶体是否瞬移（`【R-47】`）。
   - **货物双重模拟**：主机合爪后，客户端画面里的晶体是否与主机一致、是否推动客户端甲板（`【R-46】`）。
   - **带宽**：4 人同屏跑动 + 平台行驶，观察 `act4_sync` 是否报分片失败/MTU 超限（`【R-49】`）；同时看 `Network` 面板的 in/out 是否随静止而下降（未去重则会一直满发）。
   - **重绑/切角色**：同一进程内重新主持或主机↔客户端切换后，会话是否单向；一次拾取是否只计 1 点参与度（`【R-53】`）。
10. **重置残留**：任意阶段按 R、切 Act、断线重连后，门/爪/爪挡/压板/绞盘/晶体状态是否干净（`test_reset.gd` 已覆盖 Act5 主线，Act4 需手测）。

## 8. 附：本次审计对“清单式猜测”的两条纠偏（写进团队知识库）

1. **`sync_to_physics = false` 不是缺陷。** `moving_cart.gd:89` 与 `freight_platform.gd:276` 的写法经实测（E10）是**更稳**的选择：载人滑移 1e-7 m，`platform_velocity` 读数正确。改 `true` 反而会让载人下陷 0.41 m。**结论：不要为了“符合文档”把它改成 true。**
2. **矿车不会因速度隧穿。** 1.55 m/s = 25.8 mm/tick，甲板碰撞 180 mm，且速度被牵引力（1200 N）与调节器（2500 N）双重限制，代码中不存在超过 `CRUISE` 的路径。**结论：不需要连续碰撞检测（CCD）或加厚甲板。**
