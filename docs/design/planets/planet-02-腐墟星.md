# planet-02 腐墟星

`ruin` 是腐墟星在代码和联机同步中的阶段 ID；显示名称统一使用“腐墟星”。本关卡沿用霜烬星（planet-00）建立的公共接口，不重新实现联机、交互和任务骨架。

## 为什么值得做这一颗

霜烬星的压力来源是**温度**：它逼你不停移动，在热源之间接力。如果第二颗星球继续用“环境数值慢慢掉血”的套路，玩家会觉得是同一关换了张贴图。

腐墟星把压力轴换成**声音**：

- 站在安全屋里是安全的，但目标不会在安全屋里。
- 想拿东西就得发出声音，发出声音就会有人来。
- 霜烬星教你“动起来才能活”，腐墟星教你“停下来才能活”。两条规则互相矛盾，所以两颗星玩起来手感完全不同，但共用同一套玩家、交互和联机代码。

另外，这一关天然产出**只有多人才能做到**的配合——制造声响引开敌群、其他人趁机取物。这是霜烬星没能提供的东西（霜烬星的配合主要在“分头找”和“互相救”）。

## 与霜烬星的机制对照

| 系统 | 霜烬星 | 腐墟星 |
| --- | --- | --- |
| 环境压力 | 体温与氧气，靠热源续命 | 噪音与感染，靠静止和遮蔽续命 |
| 主要节奏 | 持续移动、路线接力 | 走走停停、判断时机 |
| 扫描器 | 扫出线索与样本回波 | 扫出线索，**但扫描本身会产生噪音** |
| 敌人逻辑 | 条件触发，主动追击最近玩家 | 声音触发，涌向声源而非涌向玩家 |
| 加速（Shift） | 代价是更快失温耗氧 | 代价是**大幅提高噪音**，等于主动敲钟 |
| 叙事载体 | 科考队的录音与头盔 | 殖民队的分批日志，按哨站顺序解锁 |

## 建筑与内部子地图

腐墟星的建筑是**可达可进的废墟**，不是背景贴片。每座建筑分两层：

| 层 | 内容 | 本轮是否实现 |
| --- | --- | --- |
| 外部 | 灰盒体块、破损外墙、招牌、入口交互点、门外杂物 | ✅ 本轮实现 |
| 内部 | 独立子地图（货架、病床、课桌、室内感染者） | ⏸ 只留接口，内容下一轮做 |

**入口交互**：靠近建筑正门按 `E`，主机验证距离后切到**内部子地图**；内部独立结算搜刮与战斗，从出口回到星球地图的同一位置。本轮只暴露一个入口函数 `enter_building(peer_id, building_id)`，内部场景未来直接挂同一套主机权威 RPC，不新增联机骨架。

暂定三类建筑，每类先做一处灰盒：

| 建筑 | 外部特征 | 内部主要产出（未来） |
| --- | --- | --- |
| **超市** | 大跨度平顶、破损招牌、门外堆着购物车与货架 | 罐头、净水、手电 |
| **医院** | 多层体块、十字标识、急救车残骸 | 药品、绷带（单人复活物资的候选来源） |
| **学校** | 连廊与操场、旗杆、成排窗户 | 工具、零件、叙事道具 |

## 食物与物资

这一关没有热源，体温不再是压力轴，所以**食物是唯一的续航手段**。

| 物资 | 效果 | 携带代价 |
| --- | --- | --- |
| 罐头 | 恢复 1 点生命 | 不占位 |
| 净水 | 恢复 25 氧气 | 不占位 |
| 医疗包 | 恢复 2 点生命（与飞船补给同一套物品） | 占一个携带位 |

关键设计：**物资刷在会发出声音的地方**——货架、自动售货机、冰箱。翻找会产生一次噪音脉冲。于是"想回血"和"想安静"直接冲突，这是这一关最重要的取舍。

## 当前可试玩流程（草案）

1. 从飞船航线图选择腐墟星并登陆；出生点位于殖民城外缘的登陆场，布局由主机随机生成后同步。
2. 地图保持全亮，但**任何移动都会显示噪音环**——这是玩家唯一能直接看到的自身状态。
3. 用扫描器定位三座殖民哨站。扫描会产生一次噪音脉冲，所以“想找路”和“想安静”是冲突的。
4. 每座哨站按 `E` 修复信号塔，同时解锁一段殖民队记录。记录按顺序拼出他们最后做了什么。
5. 地下管网与破裂的培育舱会让进入者累积感染；感染会缩小氧气上限并放大噪音，需要回安全屋或使用药物清除。
6. 三座哨站全部完成、撤离航道清空后，撤离点开放。
7. 全员进入撤离范围保持 3 秒，任务完成并返航；全员倒地则任务失败。

## 复用的公共接口

本关卡不新增联机骨架，直接复用霜烬星已有的接口：

- `change_stage(stage)`：新增 `ruin` 阶段。
- `request_interaction(kind, id)`：信标、资源、投送、救援沿用同一套分发。
- `_world_snapshot()` / `sync_full_state(snapshot)`：随机布局与任务状态补发。
- `request_scan()` / `sync_scan_state(...)`：部署式扫描器，改为附带噪音脉冲。
- `sync_vitals(snapshot)`：在生命、氧气、体温之外增加感染值与噪音等级。
- `return_to_ship(reason)`：完成或失败返航。

需要新增的同步项只有两个：**噪音等级**与**感染值**。

## 待团队确认

以下内容不得当成团队已定方向：

1. **星球名称**——“腐墟星”为候选人之一，备选见讨论记录。
2. **与会议纪要的冲突**：纪要《已放弃的方向》明确列出“传统僵尸作为主要敌人设定”。本草案的立场是**不做传统僵尸**，而是“人类殖民队被同一种东西寄生”，敌人靠听觉行动、不会蹒跚成群，属于环境威胁而非丧尸片套路。**这个界定需要全队认可**，否则应换主题。
3. **编号**：`planet-02` 对应航线图的第二格（01 霜烬星 / 02 腐墟星 / 03 电磁星球）。
4. **归属**：原分工表中沙暴星球属于 3 号孙同恩，主题更换后是否仍由其负责。
5. 噪音与感染的数值、地下管网的规模、敌人数量曲线，全部未定。
6. 本颗星球在最终路线中的顺序，以及是否计入正式四星。
