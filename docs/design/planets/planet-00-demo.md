## 当前可试玩流程

1. 创建主机并生成玩家。
2. 点击“进入示范星球”，全部玩家移动到 4 个出生点槽位，危险区一带生成 4 只敌人。
3. 清除危险区内的敌人。玩家近身攻击距离 58，冷却 0.35 秒，每次 1 点伤害，敌人生命 3 需要命中 3 次。未清完时按 `E` 扫描会被主机拒绝，并提示“先清除危险区内的敌人”。
4. 移动到 3 个示范信标附近按 `E` 扫描：客户端检测半径 96，主机复核半径 104。
5. 界面显示 `示范目标：3 / 3`，撤离点开启。
6. 全部在线玩家同时进入撤离点，持续 3.0 秒。
7. 显示“示范星球任务完成：全体队员已成功撤离！”，可返回飞船准备区。

撤离读条要求所有在线玩家同时在范围内，任意一名玩家离开半径，读条立即清零重新计时；敌人未清完或信标未扫完时读条同样保持清零。

## 灰盒布局

| 位置 | 坐标 | 作用 |
| --- | --- | --- |
| 出生点 | (145,275)、(235,275)、(325,275)、(415,275) | 进入关卡时玩家按编号落点 |
| 资源区 A | 矩形 (72,162)–(332,352) | 4 个资源箱占位；信标 1 位于 (185,255) |
| 安全屋 / 热源 | 圆心 (490,500)，半径 42 脉冲 | 热源占位；信标 2 位于 (500,520) |
| 危险区 | 矩形 (690,175)–(880,405) | 4 只敌人与信标 3；信标 3 位于 (790,285) |
| 撤离点 | 圆心 (845,575)，半径 58 | 需要全员同时驻留 3.0 秒 |

三个信标分别落在资源区、安全屋和危险区，其中信标 3 就在敌人活动的危险区内，所以“清完敌人才扫得动信标 3”是设计上的依赖关系，不是巧合：危险区同时承担战斗压力和最后一个目标点。

当前灰盒视觉包含网格地表、分区色块、路线连接、资源箱、热源脉冲、危险区警戒条、岩柱和撤离点动画，用于让试玩者看懂路线和目标位置。

## 建立的公共接口

示范星球建立的接口包括阶段切换、主机权威交互、可靠状态同步、新玩家状态补发和关卡完成进度。后续星球应复用这些接口，不在各自关卡中重新实现联机状态。

- `change_stage(stage)`：主机切换 `ship` / `demo` / `electromagnetic`，切换时重置进度并重新分配出生点。
- `request_activate_interaction(id)`：客户端上报交互请求，主机用 `activate_*_from_peer` 校验距离后广播结果。
- `request_attack()`：客户端上报攻击，主机判定最近敌人并结算伤害。
- `sync_shared_state(stage, ids)`：新玩家加入时补发当前阶段和已完成节点。
- `complete_demo_mission()`：关卡通关广播，供资源与结算系统接入。

## 已知问题

- **中途加入的玩家看不到敌人**：敌人节点只在 `change_stage` 时于各端本地生成，`sync_shared_state` 只补发阶段和信标进度，不补发敌人。后加入的客户端会看到空旷的危险区，本地表现与主机不一致。
- **玩家生命归零没有失败处理**：当前是满血回到出生点，既不是倒地救援，也不是关卡失败，救援系统的接入点在这里。
- **资源箱和热源没有游戏效果**：两者都只是 `_draw()` 绘制的图形，没有碰撞体、没有交互，也不影响移动或氧气。
- **验证范围**：已在 Godot 4.7.2 下用无头集成测试跑通单人主机全流程（建主机 → 进关卡 → 清敌 → 扫描 3 个信标 → 撤离读条 → 返回飞船，共 13 项检查全部通过）。未验证真实多实例联机、界面按钮点击和画面表现。
