# 开始开发前的准备清单

四个人在正式写游戏系统前完成以下准备。每一项都要有人实际操作并留下结果，不能只看教程。

## 一、工具安装

每个人都安装并打开一次：

- Godot 4.x 稳定版。
- Git。
- 一个代码编辑器，例如 VS Code。
- GitHub 账号，并加入项目仓库协作者。
- 项目约定的图片和音频编辑工具，可先使用免费工具。

统一版本：四个人使用同一个 Godot 小版本，不能有人使用不同版本打开项目后直接提交工程文件。

## 二、Godot 入门练习

每个人独立完成一个小练习并提交到自己的分支：

- 创建一个 `CharacterBody2D` 玩家。
- 使用方向键移动。
- 与墙体发生碰撞。
- 放置一个可交互物体。
- 使用一个 UI 标签显示数值。
- 运行并导出一个 Windows 测试包。

练习不需要美术，方块和圆形即可。目的是让四个人都能读懂基本 Godot 工程，而不是把学习任务集中给成员1。

## 三、Git 协作练习

每个人完成一次完整流程：

```text
拉取 main
→ 创建自己的 feature 分支
→ 修改一个文件
→ 提交 commit
→ 推送分支
→ 创建 Pull Request
→ 由队友检查
→ 合并并删除分支
```

第一次练习就故意让两个人修改同一个文档，学习解决一次简单冲突。

## 四、联机前置测试

成员1先创建最小测试场景，其他三人验证：

- 四台电脑在同一局域网。
- 互相可以获取局域网 IP。
- 防火墙允许 Godot 测试程序通信。
- 一台电脑能创建主机。
- 另外三台电脑能输入 IP 加入。
- 主机能看到四个玩家。
- 一名玩家退出后，其他人收到提示。

如果局域网连接在第一周无法稳定完成，不要立即制作四个星球；先解决连接方式。

## 五、第一次会议必须做出的决定

- 成员编号确认：1号马文韬、2号陈斯齐、3号孙同恩、4号胡展赫。
- 每个人的主责和备份负责人。
- 每周固定开发时间。
- 每周计划会和试玩会的时间。
- Godot 具体版本号。
- 项目仓库的协作者权限。
- 四个星球的最终名称和颜色风格。
- 使用哪两种武器和哪两种敌人。
- 比赛或展示的最终提交时间。

## 六、第一次会议结束时的结果

会议结束时仓库中至少应有：

- 能运行的 Godot 空项目。
- `main` 分支保护或明确的合并规则。
- 成员分工表。
- 四个星球的一页设计表。
- 第一周 GitHub Issues。
- 一个可以创建和加入的局域网测试分支。

## 七、第一周 Issue 模板

建议直接创建以下任务：

- `建立 Godot 4 项目和目录结构` —— 成员1。
- `完成玩家移动和碰撞练习` —— 成员2。
- `搭建飞船灰盒场景` —— 成员3。
- `制作基础 HUD 占位界面` —— 成员4。
- `完成局域网主机和加入测试` —— 成员1、成员2协作。
- `编写四个星球的一页规则说明` —— 全员。
- `建立测试记录模板` —— 成员4。

## 八、准备完成的判断标准

只有满足以下条件，才进入第二周：

- 四个人都能独立打开项目并运行。
- 四个人都成功创建过一次分支和 Pull Request。
- 四个人都完成过一次 Godot 小练习。
- 至少两台电脑完成过局域网连接。
- 四个人知道自己的主责、备份职责和第一周交付物。
