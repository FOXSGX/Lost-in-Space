## 二、关键设计决策与权衡

### 决策 1：总时长 105.95s vs 目标 78s

**问题：** 规格里的语速（0.9/1.1/0.85/0.95x）和 78s 目标互相冲突。

**分析：**
- 按指定语速念完全部台词最短 = 106s
- 要压到 78s 需要 1.5-1.6 倍速
- 后果：沙哑/虚弱的气质全毁

**决策：** 保真人声，接受 105.95s

**补救方案（推荐）：**

```
【现有设计】
玩家靠近热阀 → 日志 1 全播（27.44s）

【改进方案】
日志 1 拆成 3 段：
  靠近热阀 → [0:00-0:12] "这是...共振能源站..."
  进入热阀交互 → [0:12-0:20] "三条热阀链连接..."
  开启第一个热阀 → [0:20-0:27] "现在...只有冻结的反应堆..."

好处：
  ✅ 分段播放符合"探索发现"的节奏
  ✅ 总听感时长感短（分散了 27s）
  ✅ 每段 8-12s 更符合玩家注意力曲线
```

**此方案下的总时长分布：**
- 日志 1：分 3 段，各 8-10s
- 日志 2：分 2 段，各 12s
- 日志 3：分 2 段，各 13s
- 日志 4：1 段，28s（隐藏日志，完整播放）

### 决策 2：TTS 方案选择

**规格要求：** ElevenLabs / Azure / Google Cloud 之一

**实际情况：** 本机无凭据

**执行方案：** edge-tts（Azure Neural 同款模型，免费无需注册）

**切换路径：** `voice_log_spec.py` 中的 `VOICE_MAP` 已预留 A/B/C 方案

```python
VOICE_MAP = {
    "eleven_labs": { ... },  # 预留接口
    "azure_official": { ... },  # 预留接口
    "google_cloud": { ... },  # 预留接口
    "edge_tts": { ... }  # 当前使用
}
```

拿到凭据后，改一行 `provider = "azure_official"` 即可切换（脚本自动调用）。

**风险说明：** edge-tts 是非官方接口，Azure 官方没有明确支持声明。长期稳定性无保证，但对当前开发周期足够。

---

### 决策 3：男声音高处理

**问题（初版踩过的坑）：**

初版对中年男声设了 −28Hz 和 −38Hz，频谱一测：
- 1-2.5kHz 只剩 1.9%（本应 12-18%）
- 150-400Hz 占 73%（本应 20-30%）
- 结果听感：**闷住的话筒，不是沙哑**

**根本原因：** 低沉靠胸腔共振峰（400-1kHz），不能靠压高频

**调整方案：**
- 改为 −8Hz / −12Hz（仅轻微压抑高频）
- 通过增加气声层和电平衰减暗示虚弱

**结果：** 可懂度恢复到 21-31%，气质保留

## 四、已知限制与改进路径

### 限制 1：TTS 无法演绎拟音

**问题：** 脚本里的 `[咳嗽声]`、`[呼吸声]`、`[虚弱的笑声]`

**当前方案：**
- 用停顿 + 气声 + 电平衰减暗示
- 可懂，但缺"催泪"效果

**改进路径（优先级）：**
1. **短期（推荐）** — 采购或录制 3-4 个拟音样本，插进混音
   - 咳嗽：150-300ms，低频突出
   - 呼吸：100-150ms，沙沙声
   - 笑声：200-400ms，虚弱的哽咽感
   - 预计成本：0.5h（采购）或 2h（自录）

2. **中期** — 用 edge-tts 的多声色输出（支持 pitch/rate 参数），动态合成
   - 需要调研 edge-tts 是否支持嵌入音效
   - 预计成本：2-3h

3. **长期** — 联系专业配音师补录完整版
   - 成本：外包

### 限制 2：edge-tts 长期稳定性

**风险：** 非官方接口，Azure 无明确支持

**缓解方案：**
- 脚本已预留 A/B/C 方案切换接口
- 拿到凭据后可一键切换到官方 Azure
- 当前 OGG 文件与方案无关（已导出），不会失效
