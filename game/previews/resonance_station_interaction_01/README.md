# 共振星能源设备 · 独立玩法样板 01

以 Godot **4.7.2 Compatibility** 打开本目录 `project.godot`，等待首次 GLB 导入后运行主场景。默认 1280×800。这里复用已验收的 Mining Station Prototype 01.1，正式关卡、矿车原件与旧样板均未覆盖。

## 亲手完成一次操作

1. 单击画面捕获鼠标。WASD 移动、鼠标转身，Shift 奔跑；Esc 释放鼠标。
2. 沿维护通道走到矿车侧面黄色踏步，实际走上六级踏板；不需要传送或攀爬快捷键。
3. 靠近甲板检修托盘上的青蓝色核心，按 **F 拿起**。
4. 携带至共振环下方插槽附近，按 **G 安装**。其他位置按 G 会解释原因并保留手中核心。
5. 定位完成、夹爪锁定后，到旁边车上控制台按 **E 激活**。
6. 观察锁止检查 → 核心充能 → 四段环体依次接通 → 稳定输出，约 4.5 秒。控制台显示已激活，并有机械/能源音效。
7. 可在开放甲板走动，再沿踏步下车。

**X**：在前方有足够空间且高度合适的支撑面安全放下。被拒绝时仍由你持有；放下后可再次 F 拾取，包括站台/地面上的核心。

**Tab**：1.65m 近景相机；**M**：静音/恢复；**F6**：重置本样板。F1–F4 是继承的静态环境参考机位，F5 返回行走，主要玩法请用跟随相机。

## 实现边界

本项目沿用正式游戏的 `repair / pickup / deposit / drop` action 名称与 E/F/G/X 按键，`carrying=3 / carrying_id / peer_id` 字段，以及阶段的 `get_stage_action_target / handle_stage_action / stage_snapshot` 接口。正式代码没有独立可直接加载的通用刚体抓取/插槽组件；这里新增的是单台设备适配器，没有再建全局背包/交互框架。

角色运动、相机、现有 ranger 模型与 ProtagonistVisual 来自 01.1/正式项目，持握姿态利用其关节节点增加。核心是原 V2.3 的六个零件组成的派生件，固定 0.72 比例。原两级 52cm 高踏步无法通过当前角色，独立副本改为六级约 26cm 踏步；真实胶囊/跨阶检查仍生效。

洞穴与矿车主体保留原静态材质与光照。可移动核心、夹爪、控制杆和发光段已独立；动态材质沿用源颜色/粗糙度/AgX，按世界位置重新计算工作灯受光。**这仍是近似动态受光，静态洞穴不会因此实时更新 GI 或接收完整核心移动阴影。** 矿车不驾驶。

单机设备由本地 host 维护。提供对象 ID、carrier_id、revision、快照与重复状态拒绝，但**没有实现真实多人 RPC、抢占仲裁、晚加入、断线或双人抬举**。

当前持握仅为程序姿态，不是双手精确 IK；狭窄栏杆处核心会收向身前避免穿透。放置采用保守碰撞包络，不支持抛掷/推拉。动画、音效和设备进度属于本轮样板实现，仍待用户手动试玩。

## 验证

`test_interaction.gd` 用实际 Input 动作/CharacterBody3D 物理连续走查完整链，记录 21 项检查和逐帧位置；没有设置角色位置模拟登车。`test_reset.gd` 单独检查重置与地面核心恢复，仅在恢复测试中布置测试物品，不移动角色。

命令行首次使用先运行 `godot --headless --editor --path <本目录> --import --quit`。图形测试示例：

```powershell
godot --path <本目录> --script res://test_interaction.gd --log-file <绝对日志路径> -- <绝对证据输出目录>
```

完整记录、真实录像与交付报告位于仓库 `work/gameplay-iterations/20261020-resonance-station-interaction-01/`。普通静态验证器在 Codex 沙箱中会因全局 user:// 缓存/日志写入限制报 fail，原始失败记录保留；这与图形输入回放结果分开记录。
