## 🎯 反馈设计原则

### 1. **即时性**
- 所有操作 **立即** 显示反馈
- 粒子效果在操作瞬间触发
- 文字提示同步出现

### 2. **清晰性**
- 使用符号增强识别：✓（成功）、×（失败）、-（伤害）
- 颜色语义明确：绿=好、蓝=中性、红=坏
- 文字简洁明了

### 3. **层次性**
- 重要操作（击杀、倒地）= 更多粒子 + 更长显示时间
- 普通操作（移动）= 轻量粒子
- 失败操作 = 简短提示

### 4. **一致性**
- 同类操作使用相似的颜色
- 粒子效果遵循统一规范
- 提示文字格式统一

### 5. **非侵入性**
- 反馈不遮挡关键游戏区域
- 粒子效果轻量，不影响性能
- 文字提示自动消失

### 新增全局变量

```gdscript
var _feedback_label: Label          # 反馈文字标签
var _feedback_timer := 0.0          # 反馈显示计时器
```

### 核心函数调用链

```
玩家操作 → handle_action() / attack_from_peer() / damage_player()
    ↓
_spawn_particle_burst() + show_feedback_rpc.rpc()
    ↓
_show_feedback() [所有客户端]
    ↓
_update_feedback() [每帧更新]
    ↓
反馈淡出消失
```

## 🚀 性能优化

### 粒子生命周期管理
- 所有粒子自动清理（0.4-0.8秒后）
- 使用 Tween 动画，无需额外脚本
- 粒子数量合理控制（12-30个）

### RPC 优化
- 使用 `call_local` 减少网络延迟
- 关键反馈标记为 `reliable`
- 粒子效果在本地生成

### 渲染优化
- 粒子使用简单几何体（Sphere）
- 材质复用
- 无复杂物理计算
