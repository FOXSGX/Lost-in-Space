## 一、矿车与车轮的真实物理结构（任务 §2 前置调查）

`game/act1/scripts/machines/act1_mine_cart.gd`：

| 问题 | 实测结论 |
|---|---|
| 矿车本体 | **`Act1MineCartRig extends AnimatableBody3D`** —— 运动学剧情体，不是刚体车辆 |
| 车轮是否有真实碰撞 | 车轮只是 `Node3D`（`_wheel_nodes`），由 `_wheel_spin` **按车速做视觉旋转**，无碰撞体、无质量 |
| 车轮是否独立刚体 | 否 |
| 车轮是否有真实旋转自由度 | 否（纯视觉） |
| 矿车移动由什么驱动 | `_physics_process` 里按 `ACCEL=1.55` / `MAX_SPEED=6.4` **脚本更新位置**，不是力驱动 |
| `begin_departure()` | 只置 `departing = true`，之后由 `_physics_process` 沿 Z 推进 |
| 停车状态 | 改造前**没有任何制动力或约束**，`parking_brake` 只把 `brake_released` 置 true |
| 解除后如何进入发车 | `_launch_conditions_ok()` 读 `brake_released` 等 6 个 flag |

**所以本轮的目标是实现"真实机构 + 真实可测的制动作用 + 由机构状态决定联锁"，而不是把矿车改造成刚体车辆**（任务允许）。

## 二、选择的制动机构与四轮实测

设计思路（按任务 §3/§4 的优先顺序）：实体制动件 → 真实运动 → 真实阻挡。

### 2.1 第一版：块闸（闸块压盘缘，摩擦制动）
- 制动手柄 `RigidBody3D` 12 kg + `HingeJoint3D`（单位基，自由轴 = 世界 +Z，沿用 001B 结论）；
- 制动盘 `RigidBody3D` 6 kg + 同轴 `HingeJoint3D`，轴马达常开 4 rad/s；
- 实测：手柄能转到 −1.367 rad（`released()` 正确），但**盘角速度始终 3.99–4.00**，闸块完全没起阻力。

### 2.2 第二版：闸块改到盘缘内侧
- 实测：`omega` 仍 3.97–4.00；原因是**臂与盘同心**（同一轴心），臂端闸块只能绕盘心同心转动，几何上永远够不到盘缘（我算错了力臂）。

### 2.3 第三版：支点外移（力臂 0.40，支点距盘心 0.62）
- 实测：手柄落到 0.927 rad 后**完全卡死**，正负马达目标速度（冲量 80）都不动 —— 闸块与盘缘互相嵌入。

### 2.4 第四版：正锁棘爪（棘爪插入带齿制动鼓）
- 结构：鼓 `RigidBody3D` 5 kg + `HingeJoint3D`（轴马达冲量 22），棘爪 `RigidBody3D` 6 kg 夹在两片静态导槽之间，只能沿 X 平移；
- 修正了两个实现错误后（见 §四），棘爪行程正常：**0 → 0.28–0.35 m**，`released()` 与 `brake_released` 同步正确；
- **但制动效果仍不成立**：鼓的角速度在"制动"与"解除"两种状态下都是 **3.9 rad/s**
  （`omega_braked=3.91 / omega_released=3.93`）。
- 根因：棘爪在 X 方向是自由的（这正是它的行程方向），**鼓的角点会把棘爪沿行程方向顶出去**；
  加 400 N 回位弹簧后仍被顶出（`travel_rest = −0.109`，即被顶入 0.11 m）。

> 结论：在"导槽 + 实体挡 + 电机驱动鼓"这套结构下，我**没能让棘爪稳定挡住鼓**。
> 摩擦方案与正锁方案都试过，都没有达到"可实测制动"的要求。

## 四、自主修复的 Bug（本轮内）

1. **`pawl_travel()` 单位错**：用组件局部坐标 `_engaged.x` 去减**世界**坐标 `global_position.x`，
   读数 −6.4 m，导致 `released()` 永远 false。改为统一局部坐标后读数正常。
2. **棘爪与鼓心互相嵌入**：棘爪初始 x 跨到 −0.19（落在鼓半径 0.26 内）→ 生成即被弹飞 6 m。
   把棘爪移到齿圈环带（半径 0.39–0.55）。
3. **齿圈与棘爪同角度重叠**：4 齿位于 0/90/180/270°，180° 那颗正好压在棘爪上 → 再改为齿错开 45°，
   最后改为**菱形鼓**（方鼓转 45°，角点伸到 0.37）。
4. **闸块与盘缘嵌入卡死**：块闸版本正负马达都推不动 → 转正锁方案（仍不成立）。

## 七、下一轮的最小可行方向（已定位）

棘爪方案失败的根因是"棘爪沿行程方向可被顶出"。有两个明确的修法：

1. **给棘爪加真实的双向限位**：在导槽两端各加一块静态挡块（当前只有抽出端有 `PawlOutStop`），
   并在制动位置一侧加一块**只能由执行器克服的挡块**（例如用第二根执行器压缩的弹簧挡块），
   使鼓的角点无法把棘爪推回；
2. **改用已验证的关节方案**：把棘爪做成**绕真实铰链转动的棘爪臂**（与 001B 锁爪同一套已验证配置：
   单位基 + 中性父节点 + transform 前置 + 马达冲量），让鼓的角点撞在**铰链约束的刚性臂**上，
   而不是可以平移的滑块上 —— 铰链约束的臂不会被推走，这是最可能一次成功的路线。

两条都不需要重构矿车（矿车仍是剧情体），只需替换棘爪的约束形式。
